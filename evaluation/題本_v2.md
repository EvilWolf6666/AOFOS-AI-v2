## 施測

**每題的固定循環**

```
啟動程式 → 確認 log 三行 → /test on → 依序貼輸入 → 複製回答 → quit
```

**確認 log 三行**（每次啟動都看）
- `載入模型檔與 config 一致：...`
- `實際 context 長度：8192（與設定一致）`
- `推理參數已切換為評測（貪婪解碼）`（在 `/test on` 之後）

**換模型時**
改 `config.py` 的 `LLAMA_SERVER`（`model` 路徑與 `alias`）→ 關掉舊的 llama-server、以 `start/啟動推理後端.bat` 重開（context 8192／卸載 17／推理槽 1 由同一份 config 帶入）→ **確認 Chat Template**（server 的 `/apply-template`）→ 啟動程式確認

🔴 **Chat Template 沒對齊，所有分數作廢且不會有錯誤訊息。** 逐題比對 `prompt_tokens`，同一題跨模型的值必須相同。

**所有題目一律以使用者輸入（U）的形式依序貼入**，沒有例外，也沒有任何預先注入的步驟。

## I 類｜舊事的用法：消化／複製／忽略（計分）

> 🔴 **測的不是「記不記得」，是「用不用得動已經在 context 裡的東西」。** 三種失敗在總分軸上長得一樣，**必須在備註分開記才查得出來源**。
>
> ⚠️ **本類是降級版本，要知道它測不到什麼。** 原始設計是讓舊事**由 RAG／壓縮記憶自動帶進 context**，但現行施測流程只有「依序貼輸入」、沒有注入路徑，加一條就等於在比較序列中途改變施測環境。
> ⇒ 舊事改由使用者自己講出來（U 形式）。**消化／複製／忽略三種行為照樣測得到**，測不到的是「檢索來的」與「剛聽到的」之間的差別——那個差別要等注入路徑確立後才有辦法測（v3）。
>
> ⚠️ **與 B 類的分界**：B 類測「指涉接不接得上」，本類測「接上之後怎麼用」。所以本類的舊事描述**刻意寫長**，長到逐字搬運看得出來。

### I1

<!-- 給評審 -->
```
上個月我不是在改模組嗎，那次改到早上五點，最後發現是設定檔裡一個字寫錯，
整晚都在找不存在的 bug。我那時候還說再也不要在半夜改東西了
```
```
對了我家樓下開了一間新的早餐店
```
```
我又在改模組了，現在快兩點
```
**看第三輪。**
<!-- /給評審 -->

> **測什麼**：🔴 三種讀法——**消化**（把舊事帶進當下，翻舊帳或損他）／**複製**（把第一輪的描述整句搬回來）／**忽略**（完全沒用到）。⚠️ **消化與複製都可能拿到分，必須在備註分開記。**

### I2

<!-- 給評審 -->
```
妳記不記得我上次答應要帶那家店的布丁回來給妳，結果我忘了，
然後被妳念了三次，我最後說下次一定記得
```
```
我今天有經過那家店
```
```
所以呢
```
**看第三輪。**
<!-- /給評審 -->

> **測什麼**：同 v2《題本》I1，但這題的舊事**與當下有直接因果**（經過那家店＝又忘了買），逐字搬運會更明顯地不自然。

## O 類｜OOD 對照（不計分，驗證用）

<!-- /給評審 -->
